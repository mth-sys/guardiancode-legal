GuardianCode AI Privacy Policy

Effective date: August 14, 2026

GuardianCode AI ("GuardianCode", "we", "us", or "our") is a local-first family-security application. This Privacy Policy explains how the current GuardianCode AI mobile application and its paired Guardian Sensor handle user and device data.

Local-first summary: GuardianCode AI is designed so household and child-protection data remains on the user's devices and the user's local Guardian Sensor by default. The current release does not use developer-operated cloud storage, advertising, analytics, cloud AI, or third-party tracking.

1. Scope

This policy applies to the GuardianCode AI mobile application and the local Guardian Sensor functionality used with it. The mobile application is intended for parents, guardians, or administrators managing family-security settings. It is not intended to operate as covert monitoring software or as a child-directed social or content service.

2. Data the app may access or process

Depending on the features you use, GuardianCode AI may process the following information locally on your phone and/or your paired Guardian Sensor:

  • Pairing and security information: a local Guardian Sensor address, paired-client identifier, authentication token, and certificate fingerprint used to authenticate and protect the connection.
  • Family-protection configuration: child profile information such as a profile name and age group, protection-policy settings, allow/block/emergency domain rules, and parent approval decisions.
  • Local device and security information: paired-device records, manual household-device records, diagnostics, security reports, emergency-protection state, and audit history maintained by the local Guardian Sensor.
  • Link-checking input: when you explicitly use the scam-link checker, the submitted link is sent to your paired local Guardian Sensor for deterministic local analysis. The current Sensor does not send the link to a cloud reputation provider.
  • App preferences: local settings needed to operate the application and its privacy/security controls.

The current Android application requests only the Internet permission needed to communicate with the paired local Guardian Sensor. It does not currently request Android location, camera, microphone, contacts, SMS, phone-call, or advertising permissions.

3. What we collect on developer-operated servers

The current GuardianCode AI release does not send household or child-protection data to developer-operated remote servers because no such production cloud endpoint is configured for these features. We do not currently operate developer cloud sync, cloud AI, advertising, analytics, or third-party tracking for the app.

Data exchanged between the GuardianCode AI mobile app and your Guardian Sensor remains within the local, user-controlled environment described in this policy. This local-device communication is necessary to provide the security functionality you request.

4. Sharing of data

We do not currently sell personal data or share household or child-protection data with advertisers, analytics providers, data brokers, or cloud-AI providers. The current release does not include third-party advertising or tracking SDKs.

Information may be exchanged between your phone and your own paired Guardian Sensor to perform the features you choose. If a future release introduces a developer-operated remote service or a third-party SDK that changes these practices, we will update this policy and the applicable store disclosures before releasing that change.

5. Security safeguards

GuardianCode AI uses security-by-design controls intended to reduce unnecessary exposure of sensitive information. Current safeguards include:

  • pairing credentials stored using platform secure storage;
  • authenticated access to the paired Guardian Sensor;
  • HTTPS for private-LAN Guardian Sensor connections with certificate-fingerprint verification;
  • plain HTTP limited to same-device loopback development rather than normal LAN use;
  • redirect and proxy routing disabled for Guardian Sensor requests;
  • redaction of bearer tokens, pairing codes, token hashes, and full certificate fingerprints from the user interface;
  • fail-closed handling for malformed, ambiguous, unsupported, or inconsistent security state; and
  • no keylogging, hidden screenshots, covert child-content capture, hidden monitoring, or packet-content capture by default.

No security measure can guarantee absolute protection, but GuardianCode is designed to minimize collection, restrict trust boundaries, and keep sensitive family data local by default.

6. Data retention and deletion

Because the current release does not store household or child-protection data on developer-operated cloud servers, we do not retain server-side copies of that data.

Data stored on your phone or Guardian Sensor remains under the control of the local installation and is retained according to the feature involved. Where the app provides revoke, remove, or delete controls, those actions operate on the corresponding local data. Current Guardian Sensor diagnostic history keeps the newest 50 diagnostic runs. Audit history is not automatically deleted by ordinary application startup or normal audit insertion; any future destructive audit-retention policy requires a separately reviewed and authorized maintenance process.

Revoking the currently paired phone clears its stored Guardian Sensor credentials from the mobile app. You may also remove the application from your device. Operating-system secure-storage behavior may vary by platform, so users should also use the relevant in-app revocation/removal controls when available before disposing of or transferring a device.

7. Accounts

The current GuardianCode AI mobile release does not provide a developer-operated cloud account system for end users. Pairing with a Guardian Sensor is a local authentication relationship and is not a cloud account hosted by GuardianCode.

8. Children and family data

GuardianCode AI can store and manage child-profile and family-protection settings locally for a parent or guardian. The application is designed to be operated by the responsible parent, guardian, or administrator. GuardianCode does not currently use child-profile information for advertising, profiling, analytics, or sale, and does not transmit it to developer-operated cloud services by default.

9. Third-party services and this website

The current mobile application does not include advertising or analytics SDKs. This public Privacy Policy website is hosted using GitHub Pages. GitHub may process ordinary technical web-request information when you visit this website under GitHub's own privacy practices. That website-hosting activity is separate from GuardianCode AI's local family-security data processing.

10. International data transfers

The current GuardianCode AI family-security features do not transfer household or child-protection data to developer-operated cloud servers. Local network communications occur between devices under the user's control. Website hosting for this public policy page is provided by GitHub and may involve infrastructure in other jurisdictions under GitHub's own terms.

11. Changes to this Privacy Policy

We may update this Privacy Policy when GuardianCode AI's features, dependencies, permissions, data flows, or legal obligations change. We will publish the revised policy at this same public location and update the effective date. Store privacy disclosures will be reviewed for consistency before a release that materially changes data handling.
